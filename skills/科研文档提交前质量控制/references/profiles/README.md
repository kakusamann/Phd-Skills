# 可选规则库（Profiles）

本目录存放不同科研文档的专项规则。它们用于补充主 Skill 的八大核心检查模块，不是主 Skill 的运行前置条件。

## 规则类型

| 目录 | 用途 | 默认加载方式 |
|---|---|---|
| document-types | 科技报告、学术论文、学位论文等文档类型差异 | 文档类型明确且对应 Profile 存在时，可加载 |
| writing-styles | 中文学术风格、英文 SCI 风格、科技报告风格等 | 仅在用户主动指定时加载 |
| formatting-standards | 学校模板、期刊指南、项目格式规范、用户自定义排版要求 | 用户提供或明确指定后加载 |
| terminology | 专业术语、缩写、标准译法和禁用写法 | 用户指定后加载；没有时可从文档临时提取术语表 |

项目专属的职责、任务书或历史约定放在 references/project-context/，仅在用户明确指定或文档与该项目上下文明确匹配时加载。

## 共同规则

1. Profile 是可选增强规则，不是主 Skill 的依赖。
2. 目录不存在、目录中没有适用文件、文件为空或无法读取时，跳过该 Profile，继续执行核心检查。
3. 不得为了加载 Profile 而反复要求用户先配置规则库。
4. 不得推断 Profile 中未写明的格式要求、语言禁忌或专业定义。
5. 用户本轮明确要求优先于 Profile；用户提供的正式模板优先于一般经验。
6. 写作风格 Profile 不得在用户未指定时自动套用。
7. 如果不同 Profile 之间冲突，先记录冲突；能依据用户指令或正式规范解决时按其执行，否则将冲突列为待确认，不自行拼凑规则。

## 使用方式

用户可以直接说“按科技报告规则检查”“采用某期刊格式”“加载我的 LCA 术语表”。如果没有提供或选择 Profile，主 Skill 仍按通用规则完整执行。

## 新建 Profile

建议从各子目录中的模板复制一份，填写明确、可验证的规则，并注明来源、版本和适用范围。避免使用“符合学术规范”“表达更专业”等无法客观执行的模糊要求。
